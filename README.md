# agent-rule-evals

给 Claude Code 这类 agent 写的规则，到底还管不管用？这个仓库记录了我自费做的一套评测：怎么出题、怎么跑、踩了哪些坑、花了多少钱，以及两个可以直接拿去用的脚本。

如果你也给 agent 写了一份越来越长的规则文件，想知道哪些可以删、哪些其实没被照做，先读 [实战指南](docs/实战指南.md)。

## 几个结论

- 规则先分三类：事实、偏好、补丁。只有补丁需要测「还要不要」，偏好要测的是「带着它会不会照做」。
- 把出错场景还原成短小干净的任务，强模型和便宜的弱模型几乎都能做对，测不出东西。接上一段真实的长对话再测，才看到差别。
- 判分会误判，模型会绕到目录外面翻答案，调用失败的那次会被算成做对。每个判错和无效都要读模型的完整操作记录。

## 里面有什么

| 路径 | 是什么 |
|-|-|
| `docs/实战指南.md` | 完整的做法、结果、花费和踩过的坑 |
| `tools/run_eval.py` | 每道题带规则、不带规则各跑几次，按模型实际做了什么判分 |
| `tools/build_history.py` | 从一次真实的 Claude Code 会话里截出指定长度的前文，接在题目前面跑 |

题目本身不在这里：我的题都来自自己真实的工作内容，没有公开。出题方法见实战指南第二节。

## 需要什么

- Python 3.9 以上
- Claude Code 命令行（`claude`）
- 测别家模型时，一个能把 Claude Code 指向对方兼容接口的包装脚本
