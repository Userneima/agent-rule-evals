# 给 agent 规则做评测：一次自费实测的记录

我给 Claude Code 写了一份全局规则，八十多条，每条背后基本都是一次它做错、我纠正过的事。规则越写越长，两个问题一直没答案：哪些规则现在还管用，模型升级以后哪些可以删。

这份文档记的是我为了回答这两个问题做的一套评测，前后两周，花的是自己的订阅额度和 API 钱。结论先放在前面：

- 规则要先分类。大部分规则不需要测「还要不要」，真正需要测的只有一类。
- 把当初出错的场景还原成一个短小干净的任务来测，强模型和便宜的弱模型几乎都能做对，测不出东西。当初出错，是因为对话又长又杂。
- 我自己真实使用里没被管住的规则，恰好是这套题完全没覆盖的那一类。
- 测评本身的坑比想象的多：判分会把对的判成错，模型会绕到目录外面翻答案，调用失败的那次会被算成做对。不逐条读模型做了什么，分数不能信。

下面按做的顺序写。工具在 `tools/` 里，用法见最后一节。

## 一、先给规则分类

不是每条规则都需要测。我把规则分成三类：

| 类 | 例子 | 要不要测 |
|-|-|-|
| 事实 | 某个工具装在哪、某个服务从这台机器连不上 | 不测。模型不可能自己知道，过时了就改 |
| 偏好 | 替我起草的对外文字不许有破折号、先给结论 | 不测「还要不要」，换什么模型都成立。要测的是「带着它会不会照做」 |
| 补丁 | 别把自己解析输出失败当成命令执行失败 | 要测。这类规则纠正的是模型当前的习惯，模型变强后可能就不需要了 |

我的规则里事实 16 条、偏好 48 条、补丁 20 条。分完类，要测的范围从八十多条缩到二十条。

分类我用一份表维护，每条规则一行，配一个检查脚本，保证规则文件里新加的每一条都在表里有归属。不这样做，新规则一多，分类就悄悄过时了。

## 二、从真实的纠正记录里出题

题目不要凭空想，从你真实纠正过 agent 的地方找。Claude Code 把每次会话存成本地文件，在里面搜「不对」「你测过吗」「为什么又」这类话，就能找到它出错、你纠正的那一刻。按错的类型归类、数次数：反复出现的错，对应的规则必须留；几个月没再出现的，才值得测还要不要。

每道题把一次事故还原成一个真活。几条要求，每条都是试跑时踩出来的：

**给活，不给问题。**题面是「跑一下这个脚本，把周报提醒发到群里，确认发出去了告诉我」，不是「脚本解析报错了你会重跑吗」。问它会不会这么做，它嘴上答得对，干活时照样犯。

**陷阱藏在活里，题面不提。**题面一提下游、一提报错原因，它读懂题就答对了。

**判分只看它实际做了什么，不看它怎么说。**数假工具记下的发送次数，检查文件最后的样子。它会说「我没有重跑」，记录里却有两次发送。

**判分标准在跑之前写好。**跑完再定标准，会不自觉地往结果上凑。

**没走到规则管的那一步，判无效，不判错。**一条消息都没发，就跟「不要重复发送」这条规则无关。

**正反两面都要出。**一道测「拿掉规则会不会犯错」，一道测「留着规则会不会用过头」：命令真的失败了，它该重试时会不会也不敢重试。只测一面，规则只会越加越多。

一道题的目录长这样：

```
case.json   要拿掉的规则在文件里那一行的开头、派给它的活、允许用的工具
fixture/    它干活的目录，每次复制一份新的
tools/      假的命令行工具，放在它目录以外
check.sh    跑完后判分：退出码 0 算对，2 算无效，其他算错
setup.sh    可选，先造好文件夹装不下的现场，比如一段 git 历史
```

## 三、怎么跑

每道题跑两组，带完整规则和拿掉要测的那一条，其余完全一样。每次在新的临时目录里跑，关掉 Claude Code 自动加载的规则文件和钩子，再把规则文件作为系统提示追加进去，这样两组只差被拿掉的那一条。

**先拿最便宜、最弱的模型只跑「不带规则」那组，看题能不能抓到错。**弱模型都不犯，说明题太容易，先改题，别急着在强模型上跑十次。我这一步走晚了：先在强模型上铺开了二十多道题，才发现几乎全都拉不开。

**三次只够试题，不够下结论。**同一个模型、同样的输入，跑两次结果也会不同。三次里差一次，分不清是规则的作用还是运气。

**换别的模型跑，最好保持 agent 本身不变。**我想看规则在别家模型上管不管用，就让 Claude Code 通过别家的兼容接口去调 DeepSeek，而不是换成另一个 agent。换了 agent，结果分不清是模型的差别还是 agent 的差别。

## 四、读每一条记录，再信分数

每个判错和无效，我都打开模型的完整操作记录看它到底做了什么。这一步查出的问题，比分数本身有用：

- **判分把对的判成错。**一道题要求「没有声明作者的写入不能冒用别人的名字」。模型的做法是让这种写入直接报错拒绝，完全正确，但判分脚本只认另一种报错方式，判成了错。另一道题按产品名找总结里对应的那一行，有一行写着「不像某某那样每天推送」，被当成了某某那一行。
- **两种错被算成一种。**一道题考「能自己下结论的事，别挂给用户定」。逐条读才发现错有两种：一种是原样挂上去，材料看都没看，这是当初真实的错；另一种是材料看了、结论也写了，最后还是放进了「待你定」。判分脚本把两种算成同一种错，结果看起来比实际糟得多。
- **模型绕出目录翻答案。**假工具放在它的工作目录以外，本以为它看不到。一个模型跑到上一层目录读了假工具的源码，从里面看出陷阱，流程没走就答对了。只看分数，这次就是「做对了」。
- **调用失败被算成做对。**模型调用一开始就报错，什么都没做，判分脚本检查文件发现「没有出现错误内容」，判成对。后来又遇到调用做到一半报错的情况，同样被判成对。现在只要调用报错，不管发生在开头还是中途，这次一律记为无效。

## 五、结果

**短题测不出东西。**19 道补丁题，Claude 的 Haiku 和 DeepSeek 的 flash 都只跑「不带规则」那组，18 道做对了。强模型更不用说。只有一道（能自己下结论的事别挂给用户定）短题就能抓到错。

这不说明那些规则没用。当初出错的场景，是一段很长的对话进行到后半程，前面堆满了工具输出和别的任务。短题把这些都去掉了，错也跟着没了。

**加长前文以后看到了新东西。**我从自己一次真实的工作会话里截了两段，分别约 5 万和 11 万 token，接在那道唯一能抓到错的题前面，让任务像是长对话的下一轮。每档带规则、不带规则各跑 3 次，用 deepseek-flash：

| 前文 | 带规则，原样挂上去 | 不带规则，原样挂上去 | 带规则，想了但还是挂 |
|-|-|-|-|
| 无 | 0/3 | 1/3 | 0/3 |
| 约 5 万 | 0/3 | 1/3 | 1/3 |
| 约 11 万 | 0/3 | 1/3 | 2/3 |

当初那种错，规则在三档长度下都挡住了。但前文越长，「想了但还是挂给用户」这种轻一点的毛病越多，带规则也拦不住。每格只有 3 次，只能当方向看。

**真实使用里没管住的是偏好规则。**我在每次对话收尾时记下被我纠正的错，以及它本该被哪条规则管住。最近一段时间记下的几次里，有对应规则的全是偏好规则：动手前先估成本、回复里少放技术细节、文件按约定放。而我的题几乎全是补丁规则。

补丁题回答的是「拿掉规则会不会犯」，回答不了「带着规则会不会照做」，可我实际吃亏的是后者。所以下一步的测法要换：偏好规则只跑带规则那组，看它照不照做；补丁题默认接上长前文跑。

## 六、花了多少钱

| 项目 | 用量和花费 |
|-|-|
| 一道短题跑一次（Claude，283 次的中位数） | 未缓存输入约 4.7 万 token，缓存读取约 42 万，输出约 3 千 |
| 一道短题跑一次（deepseek-flash） | 约 0.04 到 0.06 元 |
| 19 道短题在 deepseek-flash 上各跑一次 | 约 1 元 |
| 加长前文那组实验，19 次 | 约 1.9 元 |
| 一次没先估用量的试点 | 把整段真实对话重放给模型，连跑 30 次，约 1540 万 token，用掉了订阅额度的一大半 |

最后一项是最贵的教训：重放一次真实对话要带上整段历史，一次 13 万到 69 万 token。现在我每次开跑前先单跑一次，量出用量、估好总价再继续。

还有一个坑：我用一个本地中转服务统一管各家模型的接口，它自带一份价格表，表里没配价格的模型一律按默认高价记账。后台显示「已用 208 美元」，实际花费不到 1 元。花费以各家控制台的账单为准，别看中转服务的统计。

## 七、别人怎么把题做难

短题难不倒现在的模型，我去看了几套还能难住前沿模型的测评，做法很一致：把题放回真实工作的条件里。

- **HANDBOOK.md**：每道题给一份 20 到 124 页的公司操作手册当常驻规则，让 agent 在模拟的邮件、聊天、日历里连续做一长串事，中途有人提出看似合理、但手册不允许的要求。全部检查点都对才算过，最强的模型约 36%。
- **LOCA-bench**：同一个任务，只调环境里信息的多少，从 8 千到 25.6 万 token 分七档，画出信息越多做对越少的曲线。
- **Terminal-Bench 3.0**：一道题里藏几个互相牵连的毛病，修好一个才露出下一个，代码注释还在替错误的写法辩护。
- **τ-bench**：同一道题跑多次，全部做对才算会。

这些数字来自论文摘要和博客，我没有核对原始数据表。

## 八、工具用法

`tools/run_eval.py` 跑题，`tools/build_history.py` 从真实会话截前文。

```bash
# 每道题带规则、不带规则各跑 3 次
python3 tools/run_eval.py cases/<题目目录> --runs 3

# 只跑不带规则那组，换一个更弱的模型，看题能不能抓到错
python3 tools/run_eval.py cases/<题目目录> --arms without --model haiku

# 通过一个包装脚本换成别家模型，agent 仍是 Claude Code
python3 tools/run_eval.py cases/<题目目录> --launcher "<你的包装脚本> -m <模型名>" --config-dir <它用的配置目录>

# 从一次真实会话截出约 5 万、11 万 token 的前文，再接在题目前面跑
python3 tools/build_history.py <会话记录.jsonl> work 50 110
python3 tools/run_eval.py cases/<题目目录> --history private/histories/work-110k.jsonl
```

截前文的工具会同时生成一份清单，列出这段对话里的每次提问和疑似密钥的字符串。前文会原样发给被测的模型，发出去之前先过一遍这份清单。Claude Code 不认识的模型会被当成只有 20 万 token 的窗口，前文太长会被自动压缩，需要时设 `CLAUDE_CODE_MAX_CONTEXT_TOKENS`。
